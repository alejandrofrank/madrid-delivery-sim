## Platform
web

## Users
Hiring managers and technical reviewers evaluating an AI application portfolio are the primary audience. Visitors should understand the grocery journey before opening implementation detail. Operators use the same product to run simulations and inspect decisions.

## Product Purpose
Show how nine agent roles coordinate a Madrid grocery network, from inventory and fulfillment to dispatch, delivery and recovery. Make their responsibilities, tools, memory, permissions, model decisions and operational outcomes inspectable through the working product.

## Operating Context
Static HTML, CSS and JavaScript are backed by the Python service. The public layer contains How it works, Watch it live and Meet the agents. The For engineers menu preserves Operations, Restaurants, Inventory, Health, Traces and Architecture, including documentation search. Recorded examples provide an initial view, with access to the existing run controls where the runtime supports them. The navigation label does not change the evidence type: a recorded view must identify itself as recorded.

## Capabilities and Constraints
Preserve backend behavior, existing tests, all nine roles, existing whole-body robot models, the in-place memory explorer, and the complete engineering tool layer. Use source-native models and actual recorded Madrid routes; the illustrated parcel handoff explains role relationships rather than proving measured activity. Default demonstrations make no paid model calls. Keep private configuration, credentials, Terraform variables, state and plans out of Git. The repository remains private unless explicitly requested otherwise. Commit coherent verified changes separately and push them to the authorized repository, alejandrofrank/madrid-delivery-sim.

## Brand Commitments
The product presents itself as Madrid; the project and repository remain madrid-delivery-sim. The approved whole-product direction is warm off-white, deep green ink, one strong green action accent, a dark alternative, readable supporting text, distinct heading typography, rounded controls and soft elevation. Existing robot geometry and purpose-colored role identities remain recognizable. Bakiano identifies the external catalogue source or a named simulated fleet, not a replacement product brand.

Engineering tools retain compact plain titles, clear controls and inspectable evidence near the top. The specifically approved public story and city-led landing composition are recorded in `.impeccable/surfaces/web-landing-html.md`; their large narrative headline is a surface decision, not a default for labs. Avoid split-color or gradient headline text and decorative slogans. Use color for state, identity, selection and data. The implemented reusable system is recorded in DESIGN.md.

## Evidence on Hand
Existing simulator APIs, local tests, recorded health/evaluation artifacts, source-backed architecture chapters and D2 diagrams remain available. The landing uses the source-verified seed-42 recording in `web/data/story-replay.json`: two simulated hours, 71 of 71 deliveries on time, five of five disruptions resolved, and an operating estimate of EUR 1.4903 per delivery. These are offline simulation results, not commercial-delivery or live-model-performance claims; disruption cohorts can overlap. Screenshots and the finish review document rendered states. Missing history, unknown costs or latency, retained evidence and stale-source qualifications must remain explicit.

## Product Principles
- Explain the order, store and doorstep journey before exposing implementation detail.
- Keep the public experience and complete engineering tools connected through one shell.
- Preserve product truth, role boundaries, entity identity and source provenance.
- Distinguish recorded measurements from illustrative motion and live runtime state.
- Make decisions readable before exposing raw payloads; keep that evidence reachable.

## Accessibility & Inclusion
Target WCAG AA contrast, visible keyboard focus, readable text, useful loading/error/empty states and layouts that work on narrow screens. Respect reduced motion and pause offscreen or hidden landing playback. Keep labels and symbols alongside state colors. Preserve keyboard navigation, explicit playback controls, local overflow for dense evidence and whole-model inspection with in-place detail.
